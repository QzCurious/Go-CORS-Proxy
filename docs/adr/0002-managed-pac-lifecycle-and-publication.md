# Managed PAC lifecycle and publication

The activation-consent and user-accepted service-set portion of this decision is superseded by [ADR-0009](./0009-automatic-managed-pac-activation.md). The projection-publication model is superseded by [ADR-0011](./0011-gateway-traffic-projection-and-pac-delivery.md): Managed PAC now delivers the already-served PAC independently to each Network Service rather than deciding which projection is published. The ownership, fixed service set, serial mutation, warning, observation, and cleanup decisions below remain in force where they do not conflict with ADR-0011.

Managed System Proxy uses PAC Routing so unrelated traffic remains direct. Each Gateway Runtime activation starts one Managed PAC control lifetime, discovers every visible network service, observes its PAC setting, exposes foreign or unobservable services as excluded, and fixes every successfully observed marker-owned or empty service as the nonempty Managed PAC Service Set for that lifetime. Network-service discovery failure prevents the assessment because no complete service scope is known. Initially excluded and newly visible services wait for another activation, while every later Set freshly classifies fixed members and a selected service can recover from an observation issue on a later Set without renewed consent.

Gateway gives Managed PAC the endpoint serving each accepted PAC Projection. Managed PAC owns publication generation, versioned ownership-marked URLs, serial mutation policy, drift classification, per-service warnings, observation issues, and private Service-PAC State; it drives the Network Service external-system module for platform-neutral service discovery and per-service PAC observation and mutation. Each Set is one synchronous serialized attempt. Managed PAC freshly observes each selected setting before deciding whether to invoke a separate platform mutation. A selected service absent from fresh discovery is skipped, an observed foreign setting is preserved and reported as drift, and any failed PAC-setting observation is reported as a current observation issue without classifying its cause. Observation issues and platform mutation failures wait for a later Gateway-requested Set; Managed PAC has no internal retry or request conflation. Every Set allocates a new publication generation even when the served projection preserves effective routes. Gateway retains only the control handle and obtains a purpose-built fresh Control State containing the fixed service set, service-identified diagnostics, and the aggregate fact that Managed PAC routes the control's current endpoint. Gateway does not receive or reinterpret raw Service-PAC State and does not cache a parallel Managed PAC state.

Initial Set begins only after Gateway Runtime and its PAC Endpoint are serving. A per-service mutation failure is nonfatal, preserves the fixed service set and served projection, reports a current warning, and waits for a later Set without stopping Gateway Runtime; per-service observation issues are reported but do not make the Set fail.

Active-state cleanup separately discovers visible network services, then freshly observes, disables, and verifies every successfully observed enabled marker-owned setting. Gateway calls ownerless cleanup only when it has no live control handle; Managed PAC does not duplicate Gateway's lifecycle admission state or reject cleanup based on independently retained control ownership. Network-service discovery failure leaves the PAC cleanup subject unknown and fails cleanup. A per-service PAC observation issue is disclosed in fulfilled cleanup detail but remains outside the cleanup scope and does not prevent success; a setting that disappears, becomes inactive, or becomes foreign needs no further cleanup. Mutation failures are retained only when verification finds observed active owned residue, which is reported for a later cleanup rather than retried in a tight loop. Closing a control is the complete teardown barrier: it closes admission, cancels and quiesces current work, performs independently bounded active-state cleanup, and releases the lifetime. Ownership authorizes cleanup regardless of publication generation, while disabled retained URLs, foreign settings, and unobservable PAC settings are not active residue.
