# Separate CA Ensure from Gateway Activation

The Start Sequence composes CA Ensure and Gateway Activation as independent lifecycle operations rather than treating their consent as one activation decision. One single-flight gate covers the whole sequence from pre-cleanup through its returned outcome, preventing concurrent starts from duplicating cleanup, CA approval, or activation. After early Gateway Footprint Cleanup and configuration validation, effective `ca-trusted: false` skips trust-store inspection and CA Ensure entirely; otherwise CA Ensure obtains platform approval and leaves a successfully Installed User CA in place even if later PAC Replacement Consent is declined or Gateway Activation fails. Every later start outcome then carries the CA Ensure Result so clients can disclose that durable change before handling PAC consent or activation failure. If later work returns an infrastructure error, the sequence preserves both that error and the completed CA result rather than rolling back or hiding the durable trust change. Gateway Activation owns PAC consent, Gateway Runtime preparation, and Managed PAC installation. `UserCA install` publicly exposes CA Ensure alone, while Gateway Activation remains internal and reachable only through the Start Sequence so callers cannot bypass its prerequisites. This makes the two consent authorities and durable effects explicit, at the cost of allowing an unsuccessful start to leave a newly usable Installed User CA behind.
