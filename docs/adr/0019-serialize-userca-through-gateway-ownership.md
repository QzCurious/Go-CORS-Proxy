# Serialize UserCA through Gateway Ownership

Gateway Ownership is the sole cross-process serialization authority for UserCA work. Ownerless `serve` and `start` create long-running owners; serve fails when an owner exists, while CLI start calls the existing owner's `/start` route and exits after its result without transferring foreground ownership. Install and uninstall likewise address an existing owner, while ownerless CA lifecycle work publishes a discoverable Transient Gateway Owner before it begins. Publishing the transient owner's Gateway Router and Gateway State Cache avoids an unexplained private lease, and the owner coordinates live runtime and Managed PAC consequences around ordinary UserCA operations. Ownerless status is the read-only exception: it briefly holds the Gateway Ownership Lease without publishing discovery state, assesses coherent facts, and rediscovers if ownership acquisition loses a race. Callers do not participate in locking or lifecycle linearization. A separate cross-process CA Mutation Lease is unnecessary because Gateway Ownership prevents concurrent execution, while immutable authority generations and the atomic Active fingerprint marker remain responsible for interruption and crash consistency.

A Transient Gateway Owner cannot be promoted into a long-running owner: routed start fails while its CA mutation is active, and after that work settles the owner atomically enters Owner Ending, rejects start, removes discovery state, and releases ownership. A retried ownerless start then becomes the expected foreground owner rather than causing an install or uninstall process to remain attached.

Install and uninstall privately recompute cleanup need from the Active fingerprint marker, owned local authority generations, and owned certificates in the OS trust store. Cleanup state and failure do not cross the UserCA seam, become Gateway warnings, or create a public reconcile operation: post-rotation cleanup is retried by the next install or uninstall before another authority may be added, while uninstall reports an error unless every owned authority is removed. Install and uninstall route through an available owner but fail immediately when another CA mutation is admitted or Owner Ending has begun; there is no mutation queue. Status remains available as `userca: mutating`, and stop closes traffic before waiting for already-admitted CA work. This supersedes the CA Mutation Lease and CA command serialization clauses of ADR-0014 and ADR-0018.

The owner holds CA command admission through the complete operation: UserCA mutation and fresh Snapshot, runtime HTTPS Generation adoption or deactivation, Managed PAC refresh, and the returned command result. Competing install, uninstall, and start work therefore cannot interleave with post-UserCA Gateway consequences, while status reports `userca: mutating` and stop waits after closing traffic.

UserCA exposes only `usable` and `not-usable`; missing, invalid, expired, untrusted, mismatched, incomplete, and cleanup conditions remain private facts. Renewal due is an independent result field, assessment failure returns an error rather than an unknown state, and Gateway-owned `mutating` status is not a UserCA state.

UserCA follows the Live Configuration module shape without its live-observation semantics: `Open` obtains a non-mutating module object, `Inspect` freshly reads authoritative facts into an immutable semantic UserCA Snapshot, and `Install` and `Uninstall` return their freshly inspected post-operation snapshots. UserCA does not cache snapshots, observe files, publish revisions, bootstrap authority material on open, or expose storage paths and trust-store records.

A usable UserCA Snapshot returns defensive generic TLS certificate and signer material directly, plus expiry and renewal due, without exporting an Active authority type, raw PEM, fingerprints, or storage paths. Gateway converts that material into its immutable HTTPS Generation, so the traffic runtime and CORS proxy do not depend on UserCA types.

Install and uninstall return separate immutable result types exposing only `Current` and `Changed`. `Changed` describes the user-visible operation—installation, repair, renewal, or removal—not private cleanup activity; Gateway maps those ordinary results into its operation-specific command results. A failed final inspection returns an error rather than a guessed result.

`Open` privately selects the default UserCA storage and current-platform trust adapter. Gateway owns the three-operation interface it consumes and supplies a fake adapter in Gateway tests; UserCA storage paths, trust-store records, clocks, and platform adapters remain private test seams exercised inside the UserCA package, while proxy tests use generic TLS fixtures.

UserCA itself never caches inspection. Gateway Runtime latches the UserCA Snapshot admitted by start or returned by install or uninstall, and status through an existing owner reports that latched value without re-reading external trust changes; ownerless status inspects freshly under the Gateway Ownership Lease. External changes are therefore observed at the next ownerless status, start, install, or uninstall rather than continuously.

UserCA exposes only `ErrApprovalDenied` for caller classification. Missing, invalid, expired, mismatched, and residual facts produce a not-usable Snapshot rather than errors when inspection itself succeeds; inspection infrastructure failures and incomplete uninstall return ordinary errors, while CA contention belongs entirely to Gateway and no cleanup error type crosses the UserCA seam.

Once the Gateway Owner admits install or uninstall, the mutation is owner-owned: request cancellation and client disconnection stop waiting for the result but do not cancel the operation. Owner Stop closes traffic and waits for admitted CA work, while process interruption is recovered from immutable generations and the Active fingerprint marker by the next install or uninstall.

Graceful process termination follows Owner Stop: it enters Owner Ending, closes traffic, rejects new admission, and waits for owner-owned CA work before removing discovery state and releasing ownership. Abrupt process failure instead relies on immutable generations and the Active fingerprint marker.

UserCA uninstall has no consent concept. Gateway evaluates live HTTPS consequences and returns its operation-specific consent-required result before admitting mutation; only an accepted retry is admitted, deactivates runtime HTTPS, and invokes ordinary UserCA uninstall. Cancellation before admission changes no CA state, while admitted uninstall follows owner-owned mutation semantics.

Successful UserCA mutation remains authoritative when later Gateway work fails. Runtime HTTPS Generation adoption or Managed PAC refresh failure produces an operation-specific partial-success command result rather than CA rollback; a later idempotent install reuses the usable UserCA and retries Gateway recovery without replacing authority identity.

Install never guesses Active identity from local generations or OS trust. It repairs a valid marker-identified authority in place, rotates a renewal-due Active authority, or removes and verifies all ambiguous owned residue before creating a fresh Candidate; inability to establish that clean precondition fails before another root is added.

Accepted uninstall deactivates runtime HTTPS before UserCA removal. If removal fails or remains partial, Gateway does not reactivate interception from incidental remaining authority state; HTTPS routing stays inactive, retrying uninstall continues removal, and only a later explicit install may establish usable UserCA state and recover runtime HTTPS.

UserCA renewal remains explicit because replacing the trusted authority mutates OS trust and may require approval. Renewal due and runtime expiry instruct the user to run install; ordinary HTTPS traffic never admits authority renewal, while runtime-generated Per-Host Leaf Certificates may be renewed automatically because they require no trust-store mutation.

Per-Host Leaf Certificates are generated and renewed automatically inside one immutable HTTPS Generation. Their expiry is capped by the Active UserCA expiry, their in-memory cache is discarded on UserCA generation change, and leaf validity and cache-reuse timing remain private traffic-runtime policy rather than UserCA interface or constants.

A UserCA Snapshot records usability at inspection and remains immutable as time passes. Gateway derives effective expiry from its explicit expiry value and injected clock without re-reading OS trust: near-expiry remains usable with install guidance, while a request boundary detecting expiry atomically removes the active HTTPS Generation, tunnels directly, and reports that explicit install is required. Established connections remain unaffected, and no runtime event renews UserCA automatically.

When discovery finds no owner but Gateway Ownership Lease acquisition loses a publication race, the command rediscovers once, routes to a newly reachable owner, or returns a retryable ownership-transition result without bypassing ownership. A Transient Gateway Owner reports mutation through status, lets stop enter Owner Ending and wait, rejects competing CA mutation and start work, and cannot be promoted into a long-running owner.
