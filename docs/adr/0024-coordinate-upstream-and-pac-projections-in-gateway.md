# Coordinate Upstream List and PAC projections in Gateway

**Status:** accepted; Upstream List independence from UserCA certificate projection superseded by ADR-0025

The File Observation, Upstream List, and PAC Routing modules remain independent and are coordinated only by Gateway. Gateway Runtime owns continuous file observation and separately maintains an optional Upstream List File Sync Issue, optional Upstream List Projection Issue, effective Upstream List Projection, and PAC Projection rather than combining them into one aggregate identity. Each issue is a distinct Gateway-owned value rather than a member of a common error hierarchy: file issue identity comprises its File Unreadable or Observation Stopped kind and presented cause, while projection issue identity is its presented cause. Observation is a lifecycle resource; results, contents, and concrete errors are transient inputs rather than retained Gateway state, and an initial result establishes definite conditions before Gateway Runtime begins. File observation privately responds to watcher uncertainty by rebuilding observation and rereading the complete file: successful rebuild plus read returns current contents, successful rebuild plus failed read reports a recoverable read error, and failed rebuild reports a stopped error. The Upstream List module projects contents and owns projection identity; PAC Routing infallibly projects the effective list with HTTPS Interception and runtime endpoint state and owns PAC Projection identity.

Gateway invokes each module's equality and alone decides projection adoption, fail-closed routing, issue visibility, and cross-feature consequences. A file-observation error updates only the File Sync Issue and preserves the Projection Issue, effective Upstream List Projection, and PAC Projection. Successful contents clear the File Sync Issue before projection; projection success clears the Projection Issue and compares the candidate, while projection failure updates that Issue and compares the canonical Empty Upstream List. Projection equality suppresses only projection adoption and propagation, never an Issue change or clearing. Gateway adopts all current values resulting from one input before performing any external consequence, without giving those independently identified values a combined aggregate identity. Equivalent repeated Issues and projections are suppressed, while cleared or changed Issues remain observable.

Both Issues must be available for Inbound Adapters to present their appearance, change, and clearing. Push-based synchronization architecture remains outside this decision: subscription topic granularity, grouped snapshots, callbacks versus streams, initial replay, cross-topic ordering, and presentation-state composition are deliberately undecided, as is synchronization of successful Upstream List Projection changes and their count, warnings, or HTTPS intent.

Rejected whole-document contents return no usable projection. Gateway records that fact as the Projection Issue, selects the canonical zero-value Empty Upstream List, and uses Upstream List Projection Identity to decide whether to adopt it. For an adopted upstream change, Gateway derives a PAC Projection and uses PAC Projection Identity to decide whether to update the live PAC and notify Managed PAC. Observation failure instead preserves both current projections, and terminal observation directs restart without ending Gateway Runtime. Line-level invalid contents remain successful projections with warnings.

Gateway gives Managed PAC only a changed, already-derived PAC Projection. PAC Projection has no operational failure branch; Managed PAC owns OS publication, generation, serialization, retry, drift, and publication warnings without receiving or reinterpreting Upstream List or HTTPS Interception inputs. This supersedes ADR-0006 and ADR-0023, plus the Upstream List Source ownership portions of ADR-0014 and ADR-0016.
