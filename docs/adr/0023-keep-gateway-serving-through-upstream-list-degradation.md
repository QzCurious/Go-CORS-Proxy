# Keep Gateway serving through Upstream List degradation

**Status:** superseded by ADR-0024

Upstream List source failure is non-fatal to Gateway Runtime. Gateway starts with an empty effective list before receiving any `ListAccepted`, thereafter retains the last list it adopted when `SourceDegraded` arrives, and keeps CORS Proxy and PAC serving while presenting the underlying source or observation cause. Source publishes wholesale-conflated `ListAccepted` or custom-error `SourceDegraded` transitions: healthy semantic no-ops are suppressed, degradation errors require no equality comparison, and the first valid projection after degradation always produces `ListAccepted` so Gateway can converge even when an earlier valid transition was replaced.

Configuration Bootstrap and Source observation are independent Upstream List operations orchestrated by Gateway. Missing-file creation requires explicitly disclosed, fingerprint-bound Start consent presented separately from and before Managed PAC Consent; acceptance invokes synchronous exclusive Bootstrap, whose error becomes a non-persistent warning on that Start result without preventing Start. Gateway then opens the Source independently, without handing off, merging, or suppressing the Bootstrap error. Active observation reports its own degradation and detects later user correction, whereas terminal observation preserves its cause and requires repair plus Gateway restart without stopping the already-serving runtime. seamless-cors never replaces, repairs, rewrites, or recreates the user-managed `upstreams.txt` outside authorized Bootstrap.
